# Submission assembly plan

Turns the strategy work into four shippable deliverables, with two substantive changes recommended to the original plan:

1. **The scanner must ship a share payload, not just a diagnosis.** A report that just says "you have 47 skills, 6 duplicates" gives the user nothing to send — the solo-to-second-person funnel stage would otherwise rest on an altruistic invite, which research shows a slice of this audience actively refuses (the "never train your replacement" finding). Fix: the tool ends with a packaged bundle of the user's best skills plus a one-line install command for a teammate — the teammate's install *is* the second-person event.
2. **Read sessions, not just skill files.** Claude Code session transcripts may yield real invocation counts, turning the report headline into something no competitor can produce from git or skill files alone: "12 skills never invoked; 3 account for 78% of invocations; never-invoked skills eat 38% of your context budget."

**Deliverables:** (1) the decision doc as one published HTML page, roughly 1,800 words, 12 sections, leading with the top-down/bottom-up tension; (2) a public repo — `npx skillscan` / `pack` / `install <url>` / opt-in `--contribute`, modular checks so one can be added live in the session's final 10 minutes; (3) an evidence appendix; (4) an AI work log whose "AI was wrong" example is the NVIDIA 5x statistic overstatement caught during verification, and whose "decision AI could not make" is the ICP/channel call itself.

**Sequence:** decide + send questions + verify the transcript assumption → scanner v0 → pack/install/contribute + publish repo + friendly-user debug → outreach ships (non-negotiable) → Reddit post + assemble → freeze and submit.

**How to apply:** the differentiator is a campaign with real replies in it. The brief's floor is "ready to run"; the ceiling is "already ran." Anything that slips outreach past its date trades away the one thing that separates this from a strategy deck.
